### `nvmath.fft.FFT`

```python
FFT(operand, /, *, axes=None, options=None, execution=None, stream=None)
```

*nvmath-python 1.0.0 · class · backend: cuFFT*

Create a stateful object that encapsulates the specified FFT computations and required resources.

This object ensures the validity of resources during use and releases them when they are no longer needed to prevent misuse.

This object encompasses all functionalities of function-form APIs `fft`,
`ifft`, `rfft`, and `irfft`, which are convenience wrappers around it.
The stateful object also allows for the amortization of preparatory costs when the same
FFT operation is to be performed on multiple operands with the same problem
specification (see `reset_operand`, `reset_operand_unchecked`,
and `create_key` for more details).

Using the stateful object typically involves the following steps:

1. **Problem Specification**: Initialize the object with a defined operation and
   options.
2. **Preparation**: Use `plan` to determine the best algorithmic implementation
   for this specific FFT operation.
3. **Execution**: Perform the FFT computation with `execute`, which can be either
   forward or inverse FFT transformation.
4. **Resource Management**: Ensure all resources are released either by explicitly
   calling `free` or by managing the stateful object within a context manager.

Detailed information on each step described above can be obtained by passing in a
`logging.Logger` obj…

**Parameters**
- `operand`: A tensor (ndarray-like object). The currently supported types are `numpy.ndarray`, `cupy.ndarray`, and `torch.Tensor`.
- `axes` = `None`: The dimensions along which the FFT is performed. `axes[-1]` is the 'last transformed' axis for rffts. Currently, it is required that the axes are contiguous and include the first or the last dimension. Only up to 3D FFTs are supported.
- `options` = `None`: Specify options for the FFT as a `FFTOptions` object. Alternatively, a `dict` containing the parameters for the `FFTOptions` constructor can also be provided. If not specified, the value will be set to the default-constructed `FFTOptions` object.
- `execution` = `None`: Specify execution space options for the FFT as a `ExecutionCUDA` or `ExecutionCPU` object. Alternatively, a string ('cuda' or 'cpu'), or a `dict` with the 'name' key set to 'cpu' or 'cuda' and optional parameters relevant to the given execution space. If not specified, the execution space will be selected to match operand's storage (in GPU or host memory), and the corresponding `ExecutionCUDA` or…
- `stream` = `None`: Provide the CUDA stream to use for executing the operation. Acceptable inputs include `cudaStream_t` (as Python `int`), `cupy.cuda.Stream`, and `torch.cuda.Stream`. If a stream is not provided, the current stream from the operand package will be used. See `stream-semantics-guide` for more details on stream handling.

**Methods**
- `get_key(*, prolog=None, epilog=None)`: Get the key based on the current state of this FFT object, supplemented with the callbacks.
- `create_key(operand, *, axes=None, options=None, execution=None, prolog=None, epilog=None)`: Create a key as a compact representation of the FFT problem specification based on the given operand, axes and the FFT options.
- `create_key_from_metadata(shape, dtype, memory_space, *, strides=None, axes=None, options=None, execution=None, prolog=None, epilog=None)`: Create an FFT key from metadata.
- `plan(*, prolog=None, epilog=None, stream=None, direction=None)`: Plan the FFT.
- `reset_operand(operand, *, stream=None)`: Reset the operand held by this `FFT` instance to a new compatible operand for subsequent execution.
- `reset_operand_unchecked(operand, *, stream=None)`: This method is a performance-optimized alternative to `reset_operand` that eliminates validation and logging overhead, making it ideal for performance-critical loops where operand compatibility is gua
- `release_operand()`
- `get_input_layout()`: Returns a pair of tuples: shape and strides of the FFT input.
- `get_output_layout()`: Returns a pair of tuples: shape and strides of the FFT output.
- `execute(direction=None, stream=None, release_workspace=False)`: Execute the FFT operation.
- `free()`: Free FFT resources.

**Pitfalls**
- Workflow: construct -> `plan()` -> `execute(direction=...)` (repeatable) -> `free()`. Use it as a context manager. One object can run both forward and inverse C2C transforms.
- `execute(direction='inverse')` is unnormalized: scale by `1/n` to undo a forward transform.
- `reset_operand(new)` reuses the plan for a new array with the same shape, dtype and layout.
- Prolog/epilog device callbacks (compiled with `nvmath.fft.compile_prolog`/`compile_epilog`) fuse elementwise work into the FFT, but compiling them requires Numba with CUDA support (`RuntimeError` otherwise).

**Notes:** - The input must be Hermitian-symmetric when `FFTOptions.fft_type` is
  `'C2R'`, otherwise the result is undefined. As a specific example, if the input
  for a C2R FFT was generated using an R2C FFT with an odd last axis size, then
  `FFTOptions.last_axis_parity` must be set to `odd` to recover the original
  signal.

**Example** (verified on Tesla T4, CUDA 12.9, CuPy 14.2.0, nvmath-python 1.0.0 (2026-10-04))
```python
import numpy as np
import cupy as cp
import nvmath

x = cp.random.rand(32, 128).astype(cp.complex64)
with nvmath.fft.FFT(x, axes=[-1]) as f:
    f.plan()
    X = f.execute(direction="forward")
    x2 = cp.random.rand(32, 128).astype(cp.complex64)
    f.reset_operand(x2)                           # reuse the plan
    X2 = f.execute(direction="forward")
assert np.allclose(X.get(), np.fft.fft(x.get(), axis=-1), rtol=1e-3, atol=1e-3)
assert np.allclose(X2.get(), np.fft.fft(x2.get(), axis=-1), rtol=1e-3, atol=1e-3)
```

**See also:** `plan`, `reset_operand`, `reset_operand_unchecked`, `release_operand`, `execute`, `create_key`

Docs: https://docs.nvidia.com/cuda/nvmath-python/1.0.0/host-apis/fft/generated/nvmath.fft.FFT.html

### `nvmath.fft.compile_epilog`

```python
compile_epilog(function, element_dtype, user_info_dtype, *, name=None, representation='ltoir', compute_capability=None)
```

*nvmath-python 1.0.0 · function*

Compile a Python function to LTO-IR to provide as an epilog function for `nvmath.fft.fft` and `nvmath.fft.FFT.plan`.

**Parameters**
- `function`
- `element_dtype`: The data type of the `data_in` argument, one of `['float32', 'float64', 'complex64', 'complex128']`. It must have the same data type as that of the FFT operand for prolog functions or the FFT result for epilog functions.
- `user_info_dtype`: The data type of the `user_info` argument. It must be one of `['float32', 'float64', 'complex64', 'complex128']` or an object of type `numba.types.Type`. The offset is computed based on the memory layout (shape and strides) of the operand (input for prolog, output for epilog). If the user would like to pass additional tensor as `user_info` and access it based on the offset, it is crucial to know…
- `name` = `None`
- `representation` = `'ltoir'`
- `compute_capability` = `None`: The target compute capability, specified as a string (`'80'`, `'89'`, ...). The default is the compute capability of the current device. For cuFFT in CUDA Toolkit 12.8, 12.9 on Blackwell devices (compute capability 12.0), the default compute capability of the current device may fail to compile. As a workaround, `'50'` can be specified.

**Returns:** The function compiled to LTO-IR as `bytes` object.

**Notes:** - The user must ensure that the specified argument types meet the requirements
  listed above.

**Example** (from docstring)
```python
import cupy as cp
import nvmath
import math

B, N = 256, 1024
a = cp.random.rand(B, N, dtype=cp.float64) + 1j * cp.random.rand(B, N, dtype=cp.float64)

norm_factor = 1.0 / math.sqrt(N)

def rescale(data_out, offset, data, user_info, unused):
    data_out[offset] = data * norm_factor

with cp.cuda.Device():
    epilog = nvmath.fft.compile_epilog(rescale, "complex128", "complex128")

r = nvmath.fft.fft(a, axes=[-1], epilog=dict(ltoir=epilog))

s = cp.fft.fftn(a, axes=[-1], norm="ortho")
assert cp.allclose(r, s)
```

### `nvmath.sparse.advanced.direct_solver`

```python
direct_solver(a, b, /, *, options=None, plan_preferences=None, factorization_preferences=None, solution_preferences=None, execution=None, stream=None)
```

*nvmath-python 1.0.0 · function · backend: cuDSS · NumPy/SciPy equivalent: `scipy.sparse.linalg.spsolve`*

Solve `a @ x = b` for `x`.

This function-form API is a wrapper around the stateful `DirectSolver` object APIs and is meant for *single* use (the user needs to perform just one sparse direct solve, for example), in which case there is no possibility of amortizing preparatory costs.

Detailed information on what's happening within this function can be obtained by passing
in a `logging.Logger` object to `DirectSolverOptions` or by setting the
appropriate options in the root logger object, which is used by default:

A user can select the desired logging level and, in general, take advantage of all of
the functionality offered by the Python `logging` module.

Further examples can be found in the nvmath/examples/sparse/advanced/direct_solver (https://github.com/NVIDIA/nvmath-python/tree/main/examples/sparse/advanced/direct_solver)
directory.

**Parameters**
- `a`: The sparse operand (or sequence of operands) representing the left-hand side (LHS) of the system of equations. The LHS operand may be a (sequence of) `scipy.sparse.csr_matrix`, `scipy.sparse.csr_array`, `cupyx.scipy.sparse.csr_matrix`, or `torch.sparse_csr_tensor`. That is, the LHS is a sparse matrix or tensor in Compressed Sparse Row (CSR) format from one of the supported packages: SciPy, CuPy,…
- `b`: The ndarray/tensor or (sequence of ndarray/tensors) representing the dense right-hand side (RHS) of the system of equations. The RHS operand may be a (sequence of) `numpy.ndarray`, `cupy.ndarray`, and `torch.Tensor`. Refer to the `semantics` section for details.
- `options` = `None`: Specify options for the direct sparse solver as a `DirectSolverOptions` object. Alternatively, a `dict` containing the parameters for the `DirectSolverOptions` constructor can also be provided. If not specified, the value will be set to the default-constructed `DirectSolverOptions` object.
- `plan_preferences` = `None`: Specify plan preferences as a `DirectSolverPlanPreferences` object. Alternatively, a `dict` containing the parameters for the `DirectSolverPlanPreferences` constructor can also be provided. If not specified, the default cuDSS plan configuration will be used.
- `factorization_preferences` = `None`: Specify factorization preferences as a `DirectSolverFactorizationPreferences` object. Alternatively, a `dict` containing the parameters for the `DirectSolverFactorizationPreferences` constructor can also be provided. If not specified, the default cuDSS factorization configuration will be used.
- `solution_preferences` = `None`: Specify solution preferences as a `DirectSolverSolutionPreferences` object. Alternatively, a `dict` containing the parameters for the `DirectSolverSolutionPreferences` constructor can also be provided. If not specified, the default cuDSS solution configuration will be used.
- `execution` = `None`: Specify execution space options for the direct solver as a `ExecutionCUDA` or `ExecutionHybrid` object. Alternatively, a string ('cuda' or 'hybrid'), or a `dict` with the 'name' key set to 'cuda' or 'hybrid' and optional parameters relevant to the given execution space. The default execution space is 'cuda' and the corresponding `ExecutionCUDA` object will be default-constructed.
- `stream` = `None`: Provide the CUDA stream to use for executing the operation. Acceptable inputs include `cudaStream_t` (as Python `int`), `cupy.cuda.Stream`, and `torch.cuda.Stream`. If a stream is not provided, the current stream for the operand device will be queried from the dense RHS operand `b` package.

**Returns:** The result of the specified sparse direct solve, which has the same shape, remains on the same device, and belongs to the same package as the RHS `b`. If `b` is a sequence, the result `x` is also a sequence of ndarray/tensor, each of which has the same shape as the corresponding tensor in `b`.

**Pitfalls**
- The left-hand side must be in CSR format (SciPy, `cupyx.scipy.sparse` CSR, or a PyTorch sparse CSR tensor).
- A 2-D right-hand side must be column-major (Fortran order): use `cupy.asfortranarray(b)` or build it as `cupy.ones((k, n)).T`. C-ordered 2-D input is rejected.
- Solves many right-hand sides in one factorization, unlike `cupyx.scipy.sparse.linalg.spsolve`, which loops over the columns.
- For repeated solves with the same sparsity pattern, use the stateful `DirectSolver` (plan -> factorize -> solve) and `reset_operands`.

**Notes:** \
    The sparse direct solver solves `a @ x = b` for `x` given the left-hand side (LHS) `a` and the right-hand side
    (RHS) `b`.

    * In the simplest version with no batching, `a` is sparse (square) matrix of size `n` in Compressed Sparse Row (CSR)
      format, and `b` is a dense vector or matrix. A matrix (2D ndarray or tensor) in the RHS is treated as multiple
      column vectors corresponding to multiple solution vectors (i.e. `x` is the same shape as the RHS) to solve for.


    * Batching can be specified either **explicitly** or **implicitly**.

      * An **explicitly-batched** LHS is provided as a Python sequence of sparse CSR matrices `[a_0, a_1, ..., a_n]`.
        Likewise an explicitly-batched RHS is provided as a sequence of vectors or matrices `[b_0, b_1, ..., b_n]`.…

**Example** (verified on Tesla T4, CUDA 12.9, CuPy 14.2.0, nvmath-python 1.0.0 (2026-10-04))
```python
import numpy as np
import cupy as cp
import cupyx.scipy.sparse as sp
import nvmath

n = 200
A = sp.diags([-1.0, 4.0, -1.0], [-1, 0, 1], shape=(n, n), format='csr')
b = cp.asfortranarray(cp.random.rand(n, 3))       # 3 right-hand sides, column-major
x = nvmath.sparse.advanced.direct_solver(A, b)
assert x.shape == (n, 3)
assert np.allclose((A @ x).get(), b.get())
```
