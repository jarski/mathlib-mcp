### `cupy.asarray`

```python
asarray(a, dtype=None, order=None, *, copy=None, blocking=False)
```

*cupy 14.2.0 · function · backend: CUDA runtime (host-to-device copy) · NumPy/SciPy equivalent: `numpy.asarray`*

Converts an object to array.

This is equivalent to `array(a, dtype, copy=False, order=order)`.

**Parameters**
- `a`: The source object.
- `dtype` = `None`: Data type specifier. It is inferred from the input by default.
- `order` = `None`: ({'C', 'F', 'A', 'K'}) Whether to use row-major (C-style) or column-major (Fortran-style) memory representation. Defaults to `'K'`. `order` is ignored for objects that are not `cupy.ndarray`, but have the `__cuda_array_interface__` attribute.
- `copy` = `None`: (bool, optional) If `True`, `obj` is always copied. If `False`, prohibits copy and raises `ValueError` on failure. If `None` (default), `obj` is copied only when necessary.
- `blocking` = `False`: (bool) Default is `False`, meaning if a H2D copy is needed it would run asynchronously on the current stream, and users are responsible for ensuring the stream order. For example, writing to the source `a` without proper ordering while copying would result in a race condition. If set to `True`, the copy is synchronous (with respect to the host).

**Returns:** cupy.ndarray: An array on the current device. If `a` is already on the device, no copy is performed.

**Pitfalls**
- Copies host data to the current GPU. Transfers are often slower than the computation itself, so move data once and keep it on the GPU.
- There is no implicit conversion back: `numpy.asarray(cupy_array)` raises `TypeError`. Use `cupy.asnumpy(x)` or `x.get()`.
- Python floats and NumPy's default dtype give float64. Pass `dtype=cupy.float32` when single precision is enough: many GPUs (e.g. T4, consumer cards) have far lower FP64 throughput.

**Notes:** If `a` is an `numpy.ndarray` instance that contains big-endian data,
this function automatically swaps its byte order to little-endian,
which is the NVIDIA and AMD GPU architecture's native use.

**Example** (verified on Tesla T4, CUDA 12.9, CuPy 14.2.0, nvmath-python 1.0.0 (2026-10-04))
```python
import numpy as np
import cupy as cp

x_host = np.arange(6, dtype=np.float32).reshape(2, 3)
x = cp.asarray(x_host)             # host -> device copy
y = (x * 2).sum(axis=1)            # computed on the GPU
y_host = cp.asnumpy(y)             # device -> host copy (waits for the GPU)
assert isinstance(y, cp.ndarray) and isinstance(y_host, np.ndarray)
assert np.allclose(y_host, (x_host * 2).sum(axis=1))
```

**See also:** `numpy.asarray`

Docs: https://docs.cupy.dev/en/v14.2.0/reference/generated/cupy.asarray.html

### `cupy.asnumpy`

```python
asnumpy(a, stream=None, order='C', out=None, *, blocking=True)
```

*cupy 14.2.0 · function · backend: CUDA runtime (device-to-host copy) · NumPy/SciPy equivalent: `numpy.asarray`*

Returns an array on the host memory from an arbitrary source array.

**Parameters**
- `a`: Arbitrary object that can be converted to `numpy.ndarray`.
- `stream` = `None`: (cupy.cuda.Stream) CUDA stream object. If given, the stream is used to perform the copy. Otherwise, the current stream is used. Note that if `a` is not a `cupy.ndarray` object, then this argument has no effect.
- `order` = `'C'`: ({'C', 'F', 'A'}) The desired memory layout of the host array. When `order` is 'A', it uses 'F' if the array is fortran-contiguous and 'C' otherwise. The `order` will be ignored if `out` is specified.
- `out` = `None`: (numpy.ndarray) The output array to be written to. It must have compatible shape and dtype with those of `a`'s.
- `blocking` = `True`: (bool) If set to `False`, the copy runs asynchronously on the given (if given) or current stream, and users are responsible for ensuring the stream order. Default is `True`, so the copy is synchronous (with respect to the host).

**Returns:** numpy.ndarray: Converted array on the host memory.

**Pitfalls**
- Blocks until the GPU work that produces the array has finished (`blocking=True` by default). It is the usual implicit synchronization point; GPU timings taken without a sync measure only kernel launches.
- `x.get()` does the same for a `cupy.ndarray`.

**Example** (verified on Tesla T4, CUDA 12.9, CuPy 14.2.0, nvmath-python 1.0.0 (2026-10-04))
```python
import numpy as np
import cupy as cp

x = cp.linspace(0.0, 1.0, 5, dtype=cp.float32)
host = cp.asnumpy(x)               # same as x.get()
assert isinstance(host, np.ndarray)
assert np.allclose(host, np.linspace(0.0, 1.0, 5))
```

Docs: https://docs.cupy.dev/en/v14.2.0/reference/generated/cupy.asnumpy.html

### `cupy.cublas.batched_gesv`

```python
batched_gesv(a, b)
```

*cupy 14.2.0 · function · backend: cuBLAS (getrfBatched/getrsBatched) · NumPy/SciPy equivalent: `numpy.linalg.solve (stacked)`*

**Import:** `import cupy.cublas` (`import cupy` alone does not load `cupy.cublas`)

Solves multiple linear matrix equations using cublas<t>getr[fs]Batched().

Computes the solution to system of linear equation `ax = b`.

**Parameters**
- `a`: (cupy.ndarray) The matrix with dimension `(..., M, M)`.
- `b`: (cupy.ndarray) The matrix with dimension `(..., M)` or `(..., M, K)`.

**Returns:** cupy.ndarray: The matrix with dimension `(..., M)` or `(..., M, K)`.

**Pitfalls**
- `import cupy` does not load `cupy.cublas`: use `from cupy import cublas` or `import cupy.cublas`, otherwise `cupy.cublas.batched_gesv` raises `AttributeError`.
- Unlike `cupy.linalg.solve`, it accepts one right-hand-side vector per system, shape `(..., M)`, as well as `(..., M, K)`.
- `cupy.linalg.solve` already calls it for stacked matrices up to `cupy.cublas.get_batched_gesv_limit()`; above that size batched LU is slow, so prefer `cupy.linalg.solve` for large matrices.

**Example** (verified on Tesla T4, CUDA 12.9, CuPy 14.2.0, nvmath-python 1.0.0 (2026-10-04))
```python
import numpy as np
import cupy as cp
from cupy import cublas                           # `import cupy` alone does not load it

A = cp.random.rand(64, 12, 12) + 12 * cp.eye(12)
y = cp.random.rand(64, 12)                        # one right-hand side per system
x = cublas.batched_gesv(A, y)                     # stacked vectors are accepted here
assert x.shape == (64, 12)
assert np.allclose(cp.einsum('bij,bj->bi', A, x).get(), y.get())
```

### `cupy.cublas.gemm`

```python
gemm(transa, transb, a, b, out=None, alpha=1.0, beta=0.0)
```

*cupy 14.2.0 · function · backend: cuBLAS (gemm) · NumPy/SciPy equivalent: `alpha * (op(a) @ op(b)) + beta * out`*

**Import:** `import cupy.cublas` (`import cupy` alone does not load `cupy.cublas`)

Computes out = alpha * op(a) @ op(b) + beta * out

op(a) = a if transa is 'N', op(a) = a.T if transa is 'T',
op(a) = a.T.conj() if transa is 'H'.
op(b) = b if transb is 'N', op(b) = b.T if transb is 'T',

- `transb`

- `b`

### `cupy.einsum`

```python
einsum(*operands, **kwargs)
```

*cupy 14.2.0 · function · backend: cuBLAS (via tensordot), cuTENSOR (optional, CUPY_ACCELERATORS=cutensor) · NumPy/SciPy equivalent: `numpy.einsum`*

Evaluates the Einstein summation convention on the operands.

Using the Einstein summation convention, many common multi-dimensional array operations can be represented in a simple fashion. This function provides a way to compute such summations.

.. _cuQuantum Python: https://docs.nvidia.com/cuda/cuquantum/python/

**Parameters**
- `operands`: (sequence of arrays) These are the arrays for the operation.
- `kwargs`

**Returns:** cupy.ndarray: The calculation based on the Einstein summation convention.

**Pitfalls**
- Pairwise contractions are reduced to `tensordot`/cuBLAS GEMMs by default. With `CUPY_ACCELERATORS=cutensor` and cuTENSOR installed, CuPy can use cuTENSOR contractions instead.
- Expressions like `'bij,bj->bi'` (batched matrix-vector) are a clear, fast alternative to `matmul` with reshaping.

**Notes:** - Memory contiguity of the returned array is not always compatible with
  that of `numpy.einsum`.
- `out`, `order`, and `casting` options are not supported.
- If `CUPY_ACCELERATORS` includes `cutensornet`, the `einsum`
  calculation will be performed by the cuTensorNet backend if possible.

    - The support of the `optimize` option is limited (currently, only
      `False`, 'cutensornet', or a custom path for pairwise contraction
      is supported, and the maximum intermediate size is ignored). If
      you need finer control for path optimization, consider replacing
      `cupy.einsum` by `cuquantum.contract` instead.
    - Requires `cuQuantum Python` (v22.03+).

- If `CUPY_ACCELERATORS` includes `cutensor`, `einsum` will be
  accelerated by the cuTENSOR backend whenever possible.

**Example** (verified on Tesla T4, CUDA 12.9, CuPy 14.2.0, nvmath-python 1.0.0 (2026-10-04))
```python
import numpy as np
import cupy as cp

A = cp.random.rand(32, 8, 8)
x = cp.random.rand(32, 8)
y = cp.einsum('bij,bj->bi', A, x)                 # batched matrix-vector product
assert np.allclose(y.get(), np.einsum('bij,bj->bi', A.get(), x.get()))
```

### `cupy.linalg.cholesky`

```python
cholesky(a)
```

*cupy 14.2.0 · function · backend: cuSOLVER (potrf / potrfBatched) · NumPy/SciPy equivalent: `numpy.linalg.cholesky`*

Cholesky decomposition.

Decompose a given two-dimensional square matrix into `L * L.H`,
where `L` is a lower-triangular matrix and `.H` is a conjugate
transpose operator.

**Parameters**
- `a`: (cupy.ndarray) Hermitian (symmetric if all elements are real), positive-definite input matrix with dimension `(..., M, M)`.

**Returns:** cupy.ndarray: The lower-triangular matrix of shape `(..., M, M)`.

**Pitfalls**
- Returns the lower-triangular factor `L` with `a = L @ L.conj().T`. CuPy 14 has no `upper=` keyword (NumPy 2 does); use `L.conj().T` for the upper factor.
- A matrix that is not positive definite gives nan silently unless inside `cupyx.errstate(linalg='raise')`.
- To solve with the factor, use two `cupyx.scipy.linalg.solve_triangular` calls (`lower=True`, then `trans='C'`).

**Warning:** This function calls one or more cuSOLVER routine(s) which may yield invalid results if input conditions are not met. To detect these invalid results, you can set the `linalg` configuration to a value that is not `ignore` in `cupyx.errstate` or `cupyx.seterr`.

**Example** (verified on Tesla T4, CUDA 12.9, CuPy 14.2.0, nvmath-python 1.0.0 (2026-10-04))
```python
import numpy as np
import cupy as cp
import cupyx.scipy.linalg

n = 64
X = cp.random.rand(n, n)
A = X @ X.T + n * cp.eye(n)                       # symmetric positive definite
L = cp.linalg.cholesky(A)
assert np.allclose((L @ L.T).get(), A.get())

b = cp.random.rand(n)
y = cupyx.scipy.linalg.solve_triangular(L, b, lower=True)
x = cupyx.scipy.linalg.solve_triangular(L, y, lower=True, trans='C')
assert np.allclose((A @ x).get(), b.get())
```

- `b`: (cupy.ndarray) "Dependent variable" values with dimension `(M,)` or `(M, K)`
- `rcond` = `None`: (float, optional) Cutoff parameter for small singular values. For stability it computes the largest singular value denoted by `s`, and sets all singular values smaller than `s` to zero.

**Returns:** tuple: A tuple of `(x, residuals, rank, s)`. Note `x` is the least-squares solution with shape `(N,)` or `(N, K)` depending if `b` was two-dimensional. The sums of `residuals` is the squared Euclidean 2-norm for each column in b - a*x. The `residuals` is an empty array if the rank of a is < N or M <= N, but iff b is 1-dimensional, this is a (1,) shape array, Otherwise the shape is (K,). The `rank` of matrix `a` is an integer. The singular values of `a` are `s`.

**Pitfalls**
- Implemented with an SVD (`full_matrices=False`): robust for rank-deficient problems, but slower than QR. For tall, well-conditioned problems `qr` + `cupyx.scipy.linalg.solve_triangular` is faster.
- Returns a 4-tuple `(x, residuals, rank, s)`. `rcond=None` uses `eps * max(M, N)` (the NumPy 2 default).
- Only 2-D `a` is supported; there is no batched least squares.

**Warning:** This function calls one or more cuSOLVER routine(s) which may yield invalid results if input conditions are not met. To detect these invalid results, you can set the `linalg` configuration to a value that is not `ignore` in `cupyx.errstate` or `cupyx.seterr`.

**Example** (verified on Tesla T4, CUDA 12.9, CuPy 14.2.0, nvmath-python 1.0.0 (2026-10-04))
```python

import cupy as cp

m, n = 500, 20
A = cp.random.rand(m, n)
x_true = cp.arange(n, dtype=A.dtype)
b = A @ x_true
x, residuals, rank, s = cp.linalg.lstsq(A, b, rcond=None)

```

*cupy 14.2.0 · function · backend: cuSOLVER (gesvd; gesvdj for small batched matrices) · NumPy/SciPy equivalent: `numpy.linalg.svd`*

Singular Value Decomposition.

Factorizes the matrix `a` as `u * np.diag(s) * v`, where `u` and
`v` are unitary and `s` is an one-dimensional array of `a`'s
singular values.

**Parameters**
- `a`: (cupy.ndarray) The input matrix with dimension `(..., M, N)`.

a QR method (`gesvd`) is used.

algorithm.

### `cupyx.scipy.fft.get_fft_plan`

```python
get_fft_plan(a, shape=None, axes=None, value_type='C2C')
```

*cupy 14.2.0 · function · backend: cuFFT (plan creation)*

Generate a CUDA FFT plan for transforming up to three axes.

**Parameters**
- `a`: (cupy.ndarray) Array to be transform, assumed to be either C- or F- contiguous.
- `shape` = `None`: (None or tuple of ints) Shape of the transformed axes of the output. If `shape` is not given, the lengths of the input along the axes specified by `axes` are used.
- `axes` = `None`: (None or int or tuple of int) The axes of the array to transform. If `None`, it is assumed that all axes are transformed. Currently, for performing N-D transform these must be a set of up to three adjacent axes, and must include either the first or the last axis of the array.
- `value_type` = `'C2C'`: (str) The FFT type to perform. Acceptable values are: * 'C2C': complex-to-complex transform (default) * 'R2C': real-to-complex transform * 'C2R': complex-to-real transform

**Returns:** a cuFFT plan for either 1D transform (`cupy.cuda.cufft.Plan1d`) or N-D transform (`cupy.cuda.cufft.PlanNd`).

**Pitfalls**
- The plan can be used as a context manager (`with plan: y = cupy.fft.fft(x)`) or passed as `plan=` to `cupyx.scipy.fft` functions. Reusing it avoids plan look-ups in hot loops.
- `value_type` must match the transform: 'C2C' (default), 'R2C' for rfft, 'C2R' for irfft. A plan whose dtype, size or batch does not match the call raises `ValueError`.
- The plan is tied to the array's shape, dtype, layout and the transformed axes.

**Warning:** This API is a deviation from SciPy's, is currently experimental, and may be changed in the future version.

**Notes:** The returned plan can not only be passed as one of the arguments of
the functions in `cupyx.scipy.fftpack`, but also be used as a
context manager for both `cupy.fft` and `cupyx.scipy.fftpack`
functions:


    x = cupy.random.random(16).reshape(4, 4).astype(complex)
    plan = cupyx.scipy.fftpack.get_fft_plan(x)
    with plan:
        y = cupy.fft.fftn(x)
        # alternatively:
        y = cupyx.scipy.fftpack.fftn(x)  # no explicit plan is given!
    # alternatively:
    y = cupyx.scipy.fftpack.fftn(x, plan=plan)  # pass plan explicitly

In both cases the user created `plan` will be used.

If this function is called under the context of
`cupy.fft.config.set_cufft_callbacks`, the generated plan will
have callbacks enabled.

**Example** (verified on Tesla T4, CUDA 12.9, CuPy 14.2.0, nvmath-python 1.0.0 (2026-10-04))
```python
import numpy as np
import cupy as cp
import cupyx.scipy.fft as cufft

x = cp.random.rand(64, 128).astype(cp.complex64)
plan = cufft.get_fft_plan(x, axes=(-1,))         # plan a 1-D C2C FFT along the last axis
y = cufft.fft(x, axis=-1, plan=plan)
with plan:                                        # plan also works as a context manager
    y2 = cp.fft.fft(x, axis=-1)
assert np.allclose(y.get(), y2.get())
assert np.allclose(y.get(), np.fft.fft(x.get(), axis=-1), rtol=1e-3, atol=1e-3)
```

### `cupyx.scipy.fft.next_fast_len`

```python
next_fast_len(target, real=False)
```

*cupy 14.2.0 · function · backend: cuFFT size heuristics · NumPy/SciPy equivalent: `scipy.fft.next_fast_len`*

Find the next fast size to `fft`.

.. _cuFFT documentation:
    https://docs.nvidia.com/cuda/cufft/index.html#accuracy-and-performance

**Parameters**
- `target`: (int) The size of input array.
- `real` = `False`: (bool) `True` if the FFT involves real input or output. This parameter is of no use, and only for compatibility to SciPy's interface.

**Returns:** int: The smallest fast length greater than or equal to the input value.

**Pitfalls**
- Pad signals to `next_fast_len(n)` (sizes with small prime factors) before FFT-based convolution or correlation; awkward prime sizes are much slower.

**Notes:** It may return a different value to `scipy.fft.next_fast_len`
as pocketfft's prime factors are different from cuFFT's factors.
For details, see the `cuFFT documentation`.

**Example** (verified on Tesla T4, CUDA 12.9, CuPy 14.2.0, nvmath-python 1.0.0 (2026-10-04))
```python
import cupy as cp
from cupyx.scipy.fft import next_fast_len

n = next_fast_len(1009)                           # 1009 is prime
assert n >= 1009
x = cp.random.rand(1009)
X = cp.fft.rfft(x, n=n)                           # zero-padded transform
assert X.shape == (n // 2 + 1,)
```

### `cupyx.scipy.linalg.lu_factor`

```python
lu_factor(a, overwrite_a=False, check_finite=True)
```

*cupy 14.2.0 · function · backend: cuSOLVER (getrf) · NumPy/SciPy equivalent: `scipy.linalg.lu_factor`*

LU decomposition.

Decompose a given two-dimensional square matrix into `P * L * U`,
where `P` is a permutation matrix,  `L` lower-triangular with
unit diagonal elements, and `U` upper-triangular matrix.

**Parameters**
- `a`: (cupy.ndarray) The input matrix with dimension `(M, N)`
- `overwrite_a` = `False`: (bool) Allow overwriting data in `a` (may enhance performance)
- `check_finite` = `True`: (bool) Whether to check that the input matrices contain only finite numbers. Disabling may give a performance gain, but may result in problems (crashes, non-termination) if the inputs do contain infinities or NaNs.

**Returns:** tuple: `(lu, piv)` where `lu` is a `cupy.ndarray` storing `U` in its upper triangle, and `L` without unit diagonal elements in its lower triangle, and `piv` is a `cupy.ndarray` storing pivot indices representing permutation matrix `P`. For `0 <= i < min(M,N)`, row `i` of the matrix was interchanged with row `piv[i]`

**Pitfalls**
- Factor once with `lu_factor` and reuse the `(lu, piv)` tuple in `lu_solve` for many right-hand sides; this is cheaper than calling `solve` repeatedly.
- An exactly singular matrix does not raise: `lu_factor` issues a `RuntimeWarning` ('Diagonal number k is exactly zero. Singular matrix.') and returns, even inside `cupyx.errstate(linalg='raise')`. To get an exception, turn the warning into an error (`warnings.simplefilter('error', RuntimeWarning)`) or use `cupy.linalg.solve` under `errstate`.
- `check_finite=True` by default, which scans the input for inf/nan and forces a device sync. Pass `check_finite=False` in hot loops.

**Example** (verified on Tesla T4, CUDA 12.9, CuPy 14.2.0, nvmath-python 1.0.0 (2026-10-04))
```python
import numpy as np
import cupy as cp
from cupyx.scipy.linalg import lu_factor, lu_solve

A = cp.random.rand(100, 100) + 100 * cp.eye(100)
lu_piv = lu_factor(A, check_finite=False)
for _ in range(3):                                # reuse the factorization
    b = cp.random.rand(100)
    x = lu_solve(lu_piv, b, check_finite=False)
    assert np.allclose((A @ x).get(), b.get())
```

**See also:** `scipy.linalg.lu_factor`

### `cupyx.scipy.sparse.csr_matrix`

csr_matrix(*args, maxprint=50, **kwargs)

*cupy 14.2.0 · class · backend: cuSPARSE (SpMV/SpMM) · NumPy/SciPy equivalent: `scipy.sparse.csr_matrix`*

Compressed Sparse Row matrix.

This can be instantiated in several ways.

`csr_matrix(D)`
    `D` is a rank-2 `cupy.ndarray`.

`csr_matrix((data, (row, col)))`

    All `data`, `indices` and `indptr` are one-dimensional
    `cupy.ndarray`.

**Parameters**
- `args`

- `kwargs`

**Members:** `A`, `H`, `get_shape`, `set_shape`, `shape`, `asfptype`, `getH`, `getrow`, `getcol`, `getformat`, `getmaxprint`, `getnnz`, `format`, `get`, `diagonal`, `eliminate_zeros`, `maximum`, `minimum`, `multiply`, `setdiag`, `sort_indices`, `toarray`, `tobsr`, `tocoo`, `tocsc`, `tocsr`, `todia`, `todok`, `tolil`, `transpose`, `has_canonical_format`, `has_sorted_indices`, `count_nonzero`, `sorted_indices`, `prune`, `sum_duplicates`, `dtype`, `astype`, `conj`, `real`, `imag`, `copy`, `mean`, `power`, `maxprint`, `device`, `T`, `mT`, `ndim`, `size`, `nnz`, `asformat`, `conjugate`, `trace`, `dot`, `nonzero`, `reshape`, `sum`, `todense`, `max`

**Pitfalls**
- Only bool, float32, float64, complex64 and complex128 values are supported. Integer data raises `ValueError`; cast to float first.
- Create it on the GPU from `(data, indices, indptr)` CuPy arrays, from a dense CuPy array, or from a SciPy sparse matrix (copied to the device).
- `csr_matrix * x` is a matrix product (SciPy spmatrix semantics), but `csr_array * x` is elementwise. Use `A @ x` to be unambiguous.
- Index arrays are int32 by default, and some cuSPARSE/cuSOLVER paths (e.g. `spsolve`) require int32 indices.

**Example** (verified on Tesla T4, CUDA 12.9, CuPy 14.2.0, nvmath-python 1.0.0 (2026-10-04))
```python
import numpy as np
import cupy as cp
import cupyx.scipy.sparse as sp

data = cp.asarray([1.0, 2.0, 3.0, 4.0])
indices = cp.asarray([0, 2, 1, 2], dtype=cp.int32)
indptr = cp.asarray([0, 2, 3, 4], dtype=cp.int32)
A = sp.csr_matrix((data, indices, indptr), shape=(3, 3))
x = cp.asarray([1.0, 1.0, 1.0])
y = A @ x                                         # cuSPARSE SpMV
assert np.allclose(y.get(), [3.0, 3.0, 4.0])
assert np.allclose(A.toarray().get(), [[1, 0, 2], [0, 3, 0], [0, 0, 4]])
```

### `cupyx.scipy.sparse.diags`

```python
diags(diagonals, offsets=0, shape=None, format=None, dtype=None)
```

*cupy 14.2.0 · function · backend: CuPy kernels (sparse construction) · NumPy/SciPy equivalent: `scipy.sparse.diags`*

Construct a sparse matrix from diagonals.

**Parameters**
- `diagonals`: (sequence of array_like) Sequence of arrays containing the matrix diagonals, corresponding to `offsets`.
- `offsets` = `0`: (sequence of int or an int) Diagonals to set: - k = 0 the main diagonal (default) - k > 0 the k-th upper diagonal - k < 0 the k-th lower diagonal
- `shape` = `None`: (tuple of int) Shape of the result. If omitted, a square matrix large enough to contain the diagonals is returned.
- `format` = `None`: ({"coo", "csc", "csr", "dia"}) Matrix format of the result. By default (format=None) an appropriate sparse matrix format is returned. This choice is subject to change.
- `dtype` = `None`: (dtype) Data type of the matrix.

**Returns:** cupyx.scipy.sparse.spmatrix: Generated matrix.

**Pitfalls**
- Pass `format='csr'` when the matrix goes to SpMV or a solver. The default format is unspecified and may change.

**Notes:** This function differs from `spdiags` in the way it handles
off-diagonals.

The result from `diags` is the sparse equivalent of::

    cupy.diag(diagonals[0], offsets[0])
    + ...
    + cupy.diag(diagonals[k], offsets[k])

Repeated diagonal offsets are disallowed.

**Example** (verified on Tesla T4, CUDA 12.9, CuPy 14.2.0, nvmath-python 1.0.0 (2026-10-04))
```python
import numpy as np
import cupy as cp
import cupyx.scipy.sparse as sp

n = 5
lap = sp.diags([-1.0, 2.0, -1.0], [-1, 0, 1], shape=(n, n), format='csr')   # 1-D Laplacian
assert lap.format == 'csr'
assert np.allclose(lap.toarray().get()[1, :3], [-1.0, 2.0, -1.0])
```

### `cupyx.scipy.sparse.linalg.eigsh`

```python
eigsh(a, k=6, *, which='LM', v0=None, ncv=None, maxiter=None, tol=0, return_eigenvectors=True)
```

*cupy 14.2.0 · function · backend: cuSPARSE (SpMV), cuBLAS, Lanczos (thick restart) · NumPy/SciPy equivalent: `scipy.sparse.linalg.eigsh`*

**Import:** `import cupyx.scipy.sparse.linalg` (`import cupyx` alone does not load `cupyx.scipy.sparse.linalg`)

Find `k` eigenvalues and eigenvectors of the real symmetric square matrix or complex Hermitian matrix `A`.

Solves `Ax = wx`, the standard eigenvalue problem for `w` eigenvalues
with corresponding eigenvectors `x`.

**Parameters**
- `a`: (ndarray, spmatrix or LinearOperator) A symmetric square matrix with dimension `(n, n)`. `a` must `cupy.ndarray`, `cupyx.scipy.sparse.spmatrix` or `cupyx.scipy.sparse.linalg.LinearOperator`.
- `k` = `6`: (int) The number of eigenvalues and eigenvectors to compute. Must be `1 <= k < n`.
- `which` = `'LM'`: (str) 'LM' or 'LA' or 'SA'. 'LM': finds `k` largest (in magnitude) eigenvalues. 'LA': finds `k` largest (algebraic) eigenvalues. 'SA': finds `k` smallest (algebraic) eigenvalues.
- `v0` = `None`: (ndarray) Starting vector for iteration. If `None`, a random unit vector is used.
- `ncv` = `None`: (int) The number of Lanczos vectors generated. Must be `k + 1 < ncv < n`. If `None`, default value is used.
- `maxiter` = `None`: (int) Maximum number of Lanczos update iterations. If `None`, default value is used.
- `tol` = `0`: (float) Tolerance for residuals `||Ax - wx||`. If `0`, machine precision is used.
- `return_eigenvectors` = `True`: (bool) If `True`, returns eigenvectors in addition to eigenvalues.

**Returns:** tuple: If `return_eigenvectors is True`, it returns `w` and `x` where `w` is eigenvalues and `x` is eigenvectors. Otherwise, it returns only `w`.

**Pitfalls**
- `which` supports only 'LM' (default), 'LA' and 'SA'. SciPy's 'SM' and shift-invert (`sigma=`) are not available.
- Everything after `k` is keyword-only: `eigsh(A, 3, 'SA')` raises `TypeError`; write `eigsh(A, k=3, which='SA')`.
- Needs `k < n`. For small dense problems, `cupy.linalg.eigh` is simpler and faster.

**Notes:** This function uses the thick-restart Lanczos methods
(https://sdm.lbl.gov/~kewu/ps/trlan.html).

**Example** (verified on Tesla T4, CUDA 12.9, CuPy 14.2.0, nvmath-python 1.0.0 (2026-10-04))
```python
import numpy as np
import cupy as cp
import cupyx.scipy.sparse as sp
from cupyx.scipy.sparse.linalg import eigsh

n = 100
A = sp.diags([-1.0, 2.0, -1.0], [-1, 0, 1], shape=(n, n), format='csr')
w = eigsh(A, k=3, which='LA', return_eigenvectors=False)
expected = 2 - 2 * np.cos(np.pi * np.arange(n - 2, n + 1) / (n + 1))   # analytic spectrum
assert np.allclose(np.sort(w.get()), np.sort(expected), atol=1e-6)
```

### `cupyx.scipy.sparse.linalg.spsolve`

```python
spsolve(A, b)
```

*cupy 14.2.0 · function · backend: cuSOLVER (csrlsvqr, sparse QR) · NumPy/SciPy equivalent: `scipy.sparse.linalg.spsolve`*

**Import:** `import cupyx.scipy.sparse.linalg` (`import cupyx` alone does not load `cupyx.scipy.sparse.linalg`)

Solves a sparse linear system `A x = b`

**Parameters**
- `A`: (cupyx.scipy.sparse.spmatrix) Sparse matrix with dimension `(M, M)`.
- `b`: (cupy.ndarray) Dense vector or matrix with dimension `(M)` or `(M, N)`.

**Returns:** cupy.ndarray: Solution to the system `A x = b`.

**Pitfalls**
- Uses cuSOLVER's sparse QR (`csrlsvqr`). Non-CSR input is converted with a `SparseEfficiencyWarning`, so build the matrix in CSR format.
- A 2-D `b` is solved one column at a time (slow for many right-hand sides). For large systems or many right-hand sides consider `nvmath.sparse.advanced.direct_solver` (cuDSS).
- `b` is cast to `A.dtype`.

**Example** (verified on Tesla T4, CUDA 12.9, CuPy 14.2.0, nvmath-python 1.0.0 (2026-10-04))
```python
import numpy as np
import cupy as cp
import cupyx.scipy.sparse as sp
from cupyx.scipy.sparse.linalg import spsolve

n = 50
A = sp.diags([1.0, 4.0, 1.0], [-1, 0, 1], shape=(n, n), format='csr')
b = cp.arange(n, dtype=cp.float64)
x = spsolve(A, b)
assert np.allclose((A @ x).get(), b.get())
```

**Notes:** This is a naive implementation using cupyx.scipy.sparse.linalg.eigsh as

This function generates a random sparse matrix. First it selects non-zero

If it is not given, the default state is used. This state is used to generate random indexes for nonzero entries.
- `data_rvs` = `None`: (callable) A function to generate data for a random matrix. If it is not given, `random_state.rand` is used.

### `cupyx.scipy.sparse.safely_cast_index_arrays`

```python
safely_cast_index_arrays(A, idx_dtype=numpy.int32, msg='')
```

*cupy 14.2.0 · function*

Safely cast sparse array indices to `idx_dtype`.

Check the shape of *A* to determine if it is safe to cast its index
arrays to dtype *idx_dtype*.  If any dimension in shape is larger than
fits in the dtype, casting is unsafe so raise `ValueError`.
If safe, cast the index arrays to `idx_dtype` and return the result
without changing the input *A*.  The caller can assign the results to
*A*'s attributes if desired or use the recast index arrays directly.

Unless downcasting is needed, the original index arrays are returned.
You can test e.g. `A.indptr is new_indptr` to see if downcasting
occurred.

**Parameters**
- `A`: (cupyx.scipy.sparse) The array for which index arrays should be (potentially) downcast.
- `idx_dtype` = `numpy.int32`: (dtype) Desired index dtype. Defaults to `numpy.int32`.
- `msg` = `''`: (str, optional) String appended to the `ValueError` message when `A.shape` is too big to fit in `idx_dtype`.

**Returns:** ndarray or tuple of ndarrays: For CSR/CSC, `(indices, indptr)`. For COO, `(row, col)` -- CuPy exposes the two coordinate arrays rather than SciPy's n-D `coords` tuple, and a 1-D COO array carries an all-zero `row`. For DIA, `offsets`.

**See also:** `scipy.sparse.safely_cast_index_arrays`
